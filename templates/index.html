About the platform

{# ------------------------------------------------------------------ #} {# HOW IT WORKS #} {# ------------------------------------------------------------------ #}

How it works

Three steps from raw text to prediction

The full path your submission travels, from the browser to the trained model and back.

Enter a headline or article

Paste a news headline, a full article body, or both into the analysis form — or upload a TXT, PDF or DOCX document. Server-side validation confirms the text is present and within the 10,000-character limit before anything is processed.

Submit it to the pipeline

The Flask backend cleans the text with the same preprocessing used during training, vectorizes it with the fitted TF-IDF vectorizer, and passes the features to the trained classifier.

Review the result

You receive a REAL or FAKE label, a confidence percentage when the model exposes class probabilities, and a plain-language note on what that output does and does not mean.

{# ------------------------------------------------------------------ #} {# AI WORKFLOW VISUALIZATION (reflects the real pipeline) #} {# ------------------------------------------------------------------ #}

AI workflow visualization

Inside the analysis pipeline

Seven interactive stages that mirror the real code path — the exact preprocessing, vectorizer and classifier defined in model.py and train_model.py. Select a stage to inspect it.

1 · User enters a news article

A headline (up to 500 characters) and/or an article body (combined limit 10,000 characters) is submitted through the form — or extracted from an uploaded TXT, PDF or DOCX file. Flask validates the input before the model is touched. 

POST /predict   headline="..."  article="..."
# or POST /upload  document=<file>  (text extracted in memory)

2 · Text preprocessing

Headline and article are joined into one text blob. The same function is used at training time and at prediction time, so the model always sees text prepared the same way. 

model.combine_headline_and_article(headline, article)
# -> "headline article body..."

3 · Text cleaning

Lowercased, HTML tags stripped, URLs removed, punctuation and non-alphabetic characters removed, whitespace collapsed. Dependency-free and identical to the cleaning applied during training. 

model.preprocess_text(text)
# lowercase -> strip <tags> -> strip URLs
# -> strip punctuation/digits -> collapse whitespace

4 · Feature extraction

The TF-IDF vectorizer fitted during training converts the cleaned text into a sparse numeric vector, weighing terms by how distinctive they are across the training documents. 

TfidfVectorizer(max_features=5000,
                ngram_range=(1, 2),
                min_df=2, stop_words="english")
vectorizer.transform([cleaned])  # -> feature matrix

5 · Machine learning classification

The trained Logistic Regression classifier scores the feature vector and selects one class. The classifier is loaded once per process and reused for every request. 

LogisticRegression(max_iter=1000, C=1.0)
classifier.predict(features)  # -> "REAL" | "FAKE"

6 · Prediction generation

The label is normalized to REAL or FAKE. When the classifier exposes class probabilities, the probability of the predicted class is reported as confidence; when it does not, no score is produced rather than an invented one. 

confidence = predict_proba(features)[predicted_class] * 100
# None if unavailable — never fabricated

7 · Result displayed to the user

The result page renders the label, the confidence meter (or an honest note when no score exists), the submitted text, a plain-language explanation, the session counters and the standing limitation disclaimer. 

render_template("result.html", label=..., confidence=...,
                explanation=..., stats=...)  # /predict

Visual walkthrough only — it does not submit text or fake a prediction. Real predictions run when you use the analysis form.

{# ------------------------------------------------------------------ #} {# AI CAPABILITIES #} {# ------------------------------------------------------------------ #}

AI capabilities

What this platform actually does

Each capability below is implemented in the source code. Anything not listed here is not part of the application.

Machine-learning text classification

A trained scikit-learn classifier labels submitted text as REAL or FAKE using TF-IDF features built from your headline and article.

Document upload analysis

Drag-and-drop TXT, PDF and DOCX files (up to 2 MB). Text is extracted in memory, validated and sent through the same prediction pipeline — never executed, never stored.

Interactive workflow visualization

An animated seven-stage diagram of the real pipeline — input, preprocessing, cleaning, TF-IDF features, classification, prediction and result.

Confidence score

When the classifier exposes class probabilities, the predicted class probability is displayed as a percentage. If it cannot be computed, the score is omitted rather than invented.

News feed interface

Category filters, search and expandable cards. Because no news API is configured, every entry is explicitly labelled demonstration content.

AI News Assistant

A chat interface backed by transparent, rule-based responses: it explains the pipeline and predictions and shares fact-checking advice. It states its limits up front.

Session prediction history

Running totals for your current browser session — checked, real and fake — stored in the Flask session cookie and shown in the snapshot below.

Server-side validation & graceful failures

Empty and over-length input are rejected by Flask before the model runs; a missing or unreadable model file produces instructions instead of a stack trace.

Not included in this build: fact-checking against independent sources, a generative AI chatbot, live news ingestion, per-word explainability, author/date metadata analysis, and permanent storage of submitted text. These are deliberately not advertised as working features.
